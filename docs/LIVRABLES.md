3. Code corrigé et tests dans `src/` et `tests/`. **Ne pas modifier** `docs/REGLES_METIER.md`. Garder les signatures des fonctions et les scénarios positifs.

5. `docs/REVUE.md` : deux commentaires argumentés, décisions et réponses. Si aucun pair disponible : faire une **auto-revue explicitement identifiée**, sans inventer un approbateur ou un commentaire GitHub.
6. Commits aux intentions distinctes (audit, énergie, affectation, cycle/annulation, confidentialité, revue) ; pousser les mises à jour sur **la même branche**.
